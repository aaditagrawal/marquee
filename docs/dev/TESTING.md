# Host tests

Marquee's unit tests run on the JVM with Robolectric (Android framework) and Roborazzi (screenshot
comparison). They need no emulator, TV, ADB, Jellyfin server or network access, and they use only
synthetic data.

## Requirements

- JDK 21 (`JAVA_HOME`), Android SDK with platform 36 (`ANDROID_HOME`).
- Linux x86-64 for exact screenshot comparison. Goldens were recorded with Robolectric 4.17 native
  graphics on Linux; other platforms can differ by a few pixels (font rasterisation).
- About 2 GB of free memory. The build caps each test JVM heap and runs one test fork.

## Commands

```sh
./gradlew :app:testDebugUnitTest          # all unit tests; Roborazzi neither records nor compares goldens
./gradlew :app:verifyRoborazziDebug       # same tests, and every screenshot must match its golden
./gradlew :app:recordRoborazziDebug       # re-record goldens (review the diff before committing)
./gradlew :app:compareRoborazziDebug      # write *_compare.png diff images without failing
./gradlew :app:verifyRoborazziDebug --tests 'com.mav.marquee.offline.*'   # screenshots only
```

`verifyRoborazziDebug` is the full gate: it runs the whole unit-test suite and compares the 30
goldens (25 screens, 2 skip-button captures and 3 Settings open-source-licence captures). Roborazzi writes its report to `app/build/reports/roborazzi/index.html` and comparison
images to `app/build/outputs/roborazzi/`.

## What is in the suite

| Area | Tests | What they check |
| --- | --- | --- |

| Open-source licences | `offline/SettingsLicencesTest` | D-pad reaches the last Settings row (`Open-source licences`), its GPL/no-warranty/source line is shown, the list contains every file in `assets/licenses/`, D-pad moves through it, Select opens the GPL text with Close focused, Down scrolls the text, Back returns to the list and then to the row; every licence file is split into lazy chunks of at most 12 lines. Goldens `settings-end`, `settings-licences`, `settings-licence-text` |
| Skip button | `offline/SkipButtonScreenshotTest` | the focused OSD skip pill keeps its resting horizontal padding (regression guard for `OsdButton.refresh()`); resting and focused captures are goldens too |
| Navigation budgets | `ui/home/HomeNavigationTest`, `ui/library/ScreenNavigationTest`, `player/PlayerOsdTest` | every D-pad key moves focus and finishes scrolling in its first frame with no running animation; recomposition/measure/placement counts and JVM CPU time of app key handling stay within `app/src/test/resources/nav-budget.json` |
| Layout | `ui/detail/DetailLayoutTest`, `ui/home/CardFocusWorkTest`, `ui/home/CaptionAndPrefetchTest` | title/metadata gaps, Next Up alignment, focus without scaling/remeasure, caption layout caching, bounded nested prefetch |
| Playback policy | `player/StreamResolverTest`, `TranscodePolicyTest`, `AudioSelectionTest`, `SegmentPolicyTest`, `Playback*Test`, `Speculative*Test`, `BufferedLiveStreamTest`, `PlayerLifecycleTest` | PlaybackInfo → stream URL decisions (direct play, remux, HDR/Dolby Vision handling, token stripping), audio track choice, intro/credits segments, report payloads, speculative prefetch |
| Catalog | `data/CatalogIndexTest` | origin/genre shelf classification and stable row keys |
| Server address and security | `data/ServerAddressTest`, `data/ServerProbeTest`, `data/AuthOriginTest` | address canonicalisation and candidate order; the https → http rule against local sockets (plain-HTTP port falls back, trusted TLS stays on https, self-signed or mismatched certificates stop without an http attempt, explicit `http://` used as typed); the `Authorization` header only for the configured origin |

## Fixtures

All JSON under `app/src/test/resources/` (except `nav-budget.json`) is generated by
`tools/fixtures/generate.py` from a fixed seed: an invented 217-title library, an 11-episode
series, and three playback regressions whose codec/stream structure is retained while all identity
is synthetic. See `tools/fixtures/README.md` for field-level provenance.

```sh
uv run --no-project python tools/fixtures/generate.py --check   # committed files match the generator
```

Artwork is never downloaded: `OfflineServer` serves locally drawn placeholder bitmaps for every image
URL, and BlurHashes are synthetic.

## Goldens

Goldens live in `app/src/test/screenshots/` (the paths are set in the tests via
`OfflinePaths.golden()`, matching `roborazzi { outputDir }` in `app/build.gradle.kts`).

To re-record after an intended visual change:

1. `./gradlew :app:recordRoborazziDebug`
2. Inspect every changed PNG (`git diff --stat app/src/test/screenshots`, then view them). A change
   in an unrelated screen is a regression until explained.
3. `./gradlew :app:verifyRoborazziDebug` twice; both runs must pass without re-recording.

Never re-record to make an unexplained failure disappear.

`docs/media/screens/` holds a curated copy of some goldens for the README; see its `MANIFEST.md`.

## Properties and opt-in modes

| Property / environment | Default | Effect |
| --- | --- | --- |
| `-Pmarquee.navCapture=<mode>` | `verify` | `verify` asserts the budgets. `before`, `screens-before`, `screens-after`, `instant-*` only record counters (for A/B comparison against older code) and skip some or all budget assertions. Reports go to `app/build/offline-evidence/`. CI must use the default. |
| `-Pmarquee.navCaptionLayouts=false` | `true` | Disables cached card-caption layouts in `HomeNavigationTest` (control measurement only). |
| `marquee.projectRoot` (set by the build) | repository root | Used to read `docs/device-profile.json` and the optional maintainer inputs below. Falls back to `..` when a test is launched without the build's system properties. |
| `bench/evidence/offline-player/items.json`, `bench/evidence/audio-remux/{library,playback-info}.json` | absent | Opt-in maintainer exports in `StreamResolverTest`/`AudioSelectionTest`. Reported as **skipped** when absent. |
| `MARQUEE_SPECULATIVE_LIVE=1` plus `JF_URL`, `JF_API_KEY`, `JF_TV_USER_ID`, `MARQUEE_SPECULATIVE_ITEM_ID`, `JF_LOG_DIR` | unset | `SpeculativeLiveHarnessTest` talks to a Jellyfin server you control. Skipped otherwise. Never run it in CI. |
| `-Pmarquee.loginRender=<phase>` | unset | `login/LoginRenderTest` writes a login-screen render for documentation; skipped otherwise. |

A clean checkout therefore reports five skipped tests: the three opt-in exports/replays, the live
harness and the login render.

The test JVM runs with `user.timezone=UTC`, Robolectric's default `en-US` configuration and its bundled fonts. `OfflineApplication` simulates the reference TV (manufacturer/model and a 192 MB memory class, so the bitmap cache matches the device budget and warmed artwork draws on the first frame; `MarqueeImages.init` resizes the cache whenever its limit differs from the budget, so a limit shrunk by an earlier test's application grows back). It also sets the Android device name to `robolectric`, because `Session.deviceName` is computed once per JVM and the Settings device line would otherwise depend on which test ran first. `SettingsLicencesTest` resets the process-wide Settings list position and focus memory before and after each case. The fixture server binds `127.0.0.1:19096`, so run one test JVM at a time (the build sets one fork); the end-time clock string in
screenshots is pinned (`OfflineDeterminism`), and search memory is reset between cases.

## Search screenshot synchronization

`OfflineScreenshotTest.searchResults` waits for the search model to finish loading and for Compose to reach idle
before checking semantics and moving focus. The previous test fetched semantics
inside the polling loop and once failed with
`performMeasureAndLayout called during measure layout`. Polling search completion on the UI thread
lets the Compose test clock advance without starting a semantics fetch on
each poll. The test still asserts that the results are present before capture.

## What these tests do not prove

- **Not frame rate.** Robolectric runs Compose on a JVM with a virtual clock. "One frame" means one
  `mainClock` tick in the test, not a 16.7 ms deadline on a TV. Recomposition/measure counts are
  structural; CPU nanoseconds are measured on the host JVM, not on an ARM TV SoC.
- **Not input latency.** Key events are dispatched in-process; no remote, IR/Bluetooth stack, or
  Android input pipeline timing is involved.
- **Not decoding or playback.** No media is decoded. Playback tests check URL/profile decisions and
  view state; whether a given TV's hardware decoders play a stream, and how fast, is only measured
  on a device (see `docs/benchmarks/`).
- **Not server compatibility.** The fixture server returns synthetic JSON shaped like Jellyfin 10.11
  responses. It does not prove compatibility with every server version or plugin.
- **Not visual quality on a TV.** Goldens are software renders of placeholder art; panel colour,
  HDR tone mapping and overscan are out of scope.
